# 工程结构

本项目采用单模块 Gradle 工程。仅保留 LeetCode 和 LeetCodeCN，两个站点复用 `leetcode` 包中的实现，通过 `CodeDojo` 区分域名、登录状态与设置。

```text
build.gradle.kts               构建、依赖、前端打包及代码生成
settings.gradle.kts            Gradle 工程入口
gradle.properties             插件与目标平台版本
gradle/                       Wrapper、jOOQ 配置及设计 schema
src/
  main/
    scala/                    插件业务与 IDEA 集成
    java/                     Java 桥接类和 UI Designer 表单
    resources/                plugin.xml、消息、模板、图标和数据库迁移
  generated/java/             检入的 jOOQ 模型与词法分析器
  test/
    scala/                    JUnit 和 ScalaTest 单元测试
    resources/                离线测试数据
webview/                      题目描述、题解页面与 Vite 配置
docs/                         开发、结构和上游历史文档
build/                        构建产物、测试报告与开发沙箱，不提交
```

## 业务边界

`leetcode` 包负责站点 API、题目查询、模板数据、测试、提交及题解。`services`、`settings`、`editor`、`toolwindows` 和 `vfs` 提供公共能力；`utils` 放置已有通用工具。保持现有包名和插件 ID，避免无业务收益的全量改名。

不再保留其他刷题平台的服务、设置、界面、动作、模板、图标、前端入口、测试及生成模型。文案和新功能统一围绕两个 LeetCode 站点维护，不预建多平台扩展层。

## 数据与兼容性

保留 `leetcode` / `leetcodecn` 持久化标识、配置组件名称、插件 ID 和现有数据库文件名。历史项目仍能使用原配置和力扣数据；其他平台的数据不会主动删除，也不会出现在提交记录列表中。

`src/main/resources/db/migration/` 中已发布的 Flyway 迁移保持原文件名与内容。虽然包含旧平台建表语句，但修改或删除会影响已安装用户的迁移校验，因此作为升级兼容记录保留；运行时代码与生成模型不再访问这些表。后续数据库调整新增迁移，不重写已执行的迁移。

IDEA 2026.2 把 JCEF 拆为独立组件，插件描述符和 Gradle 编译依赖均显式声明 JCEF。旧 233 / 241 平台分支已删除，原 252 实现合并到正常源码目录，当前以 262 平台编译和验证。

## 维护

先读取真实调用链，再做改动；保留题目提交区域标记、平台类名与函数签名契约。生成文件与对应来源一起更新。项目配置、Cookie、账号数据、缓存、临时备份和已构建的插件包不提交。
