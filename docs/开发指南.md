# 开发指南

## 环境与导入

使用 JDK 25 和 Node.js 24；重新生成 jOOQ 模型时另需 Python 3。Gradle 版本由 Wrapper 固定，npm 依赖由 `webview/package-lock.json` 固定。将 `JAVA_HOME` 指向 JDK 25，确保 `java`、`node` 和 `npm` 可用。

在 IDEA 中打开根目录并加载 Gradle 工程。Scala 代码编辑需要 IDEA 的 Scala 插件；开发本插件不要求目标 IDE 安装 Scala 插件，Scala 运行库随插件打包。UI Designer 的 `.form` 与 Java 类放在相同包目录下，Gradle 负责表单插桩。

## 常用命令

从仓库根目录执行：

```bash
# 编译、执行离线测试并生成插件 ZIP
./gradlew check buildPlugin

# 启动独立沙箱 IDE 调试
./gradlew runIde

# 检查插件工程配置
./gradlew verifyPluginProjectConfiguration

# 检查平台 API 兼容性（需要下载验证器与目标 IDE）
./gradlew verifyPlugin

# 仅构建前端
./gradlew buildWebview

# 从文本设计 schema 重新生成 jOOQ 模型（需要 Python 3）
./gradlew generateJooq
```

默认目标版本由 `gradle.properties` 的 `platformVersion` 决定，当前为 IDEA 2026.2.3；`platformSinceBuild` 限定最低平台构建号。修改后需要真实构建、API 兼容检查及客户端验收，不能仅改版本号宣布兼容。

需要复用本地 IDEA 以免重复下载时：

```bash
./gradlew check buildPlugin -PlocalPlatformPath="/path/to/IntelliJ IDEA.app"
```

本地平台路径只通过命令参数或个人 Gradle 配置提供，不写入仓库。切换目标版本时，确保该路径指向对应版本。

网络受限且构建依赖已缓存时，可以执行离线兼容性检查。Gradle 的 `--offline` 会同时传给 Plugin Verifier，使其仅解析本地已下载的插件依赖；未缓存的依赖仍会导致检查无法完成。

```bash
./gradlew verifyPlugin --offline -PlocalPlatformPath="/path/to/IntelliJ IDEA.app"
```


## 测试与验收

默认测试不调用真实力扣服务。已移除依赖个人 Cookie、固定本机代理和打印远端响应的手工 API 脚本。JUnit 与 ScalaTest 单元测试均由 Gradle 的 `test` 执行；测试报告在 `build/reports/tests/test/`。

构建成功只证明代码与打包流程通过。安装后还需人工检查：两个站点的设置和题目入口、Login 对话框与浏览器页面、拉题、模板生成、测试、提交、提交记录及题解。使用测试账号和可丢弃的沙箱项目，真实提交由使用者自行执行。

CI 在推送和 Pull Request 时运行 `check buildPlugin`，上传 ZIP 及测试报告；不自动发布到 JetBrains Marketplace。

## 生成代码

`src/generated/java/` 保存 jOOQ 模型和模板词法分析器，普通构建直接使用它们，无需开发者预装生成工具。

- 数据表定义：`gradle/schema.sql`；jOOQ 配置：`gradle/jooq.xml`。修改 schema 后执行 `generateJooq` 并检查生成差异。生成任务只覆盖数据库模型，保留词法分析器。
- 词法规则：`src/main/scala/com/wenjunhuang/codeepiphany/model/template/lexer/ChallengeFileTemplateTextLexer.flex`；生成类为同包 `_ChallengeFileTemplateTextLexer.java`。规则修改时需使用兼容的 JFlex 与 IntelliJ skeleton 重新生成并执行词法测试，普通构建不会自动重新生成。

设计 schema 用于生成模型，不用于升级用户数据库。运行时数据库迁移见[工程结构](工程结构.md)。
